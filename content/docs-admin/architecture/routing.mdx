## Proxy (`proxy.ts`)

Next.js 16 renamed `middleware.ts` to `proxy.ts`. This one does **markdown content negotiation** using `fumadocs-core/negotiation`:

| Incoming request                         | Rewritten to                   |
| ---------------------------------------- | ------------------------------ |
| `GET /` with `Accept: text/markdown`     | `/llms.md/content.md`          |
| `/docs/foo.md` (any `Accept`)            | `/llms.md/docs/foo/content.md` |
| `/docs/foo` with `Accept: text/markdown` | `/llms.md/docs/foo/content.md` |

It's a **rewrite**, so the browser URL stays the same.

## Redirects (`next.config.mjs`)

- `/docs`, `/docs.md` and `/docs.mdx` go to `/about` (permanent). The docs introduction became the about page (`app/(app)/about`, FAQ text in `constants/faq.ts`)
- `/docs/:path*.mdx` goes to `/docs/:path*.md` (permanent)
- `/homepage-new` goes to `/`, and `/homepage-new/docs/:path*` goes to `/docs/:path*` (temporary, 307). These are the browse page's old URLs

## Headers (`next.config.mjs`)

`/` responds with a `Link` header that advertises the API catalog, the OpenAPI description, the docs, the shadcn MCP docs and the agent skills index. This is for agent discovery.

## Adding a new route

1. Add the path to `ROUTES` in `constants/routes.ts`.
2. Create the folder under `app/(app)/` for a site page (the navbar and the footer), under `app/(home)/` if it belongs with the browse page and the docs (the navbar only, kept mounted between them), or directly under `app/` if it needs neither. Both groups use the same navbar, `components/new-hero-section/browse/browse-top-bar.tsx`, through `BrowseShell`. On a site page it selects no library tab, and its search opens docs pages.
3. If it should appear in the navbar, add it in `browse-top-bar.tsx` (Pricing is there now). Development-only links go in `devLinks` in `components/new-hero-section/browse/new-home.tsx`.
4. If it's public, add it to `app/sitemap.ts`. Docs pages are added automatically, except placeholders: a page in a library folder (`/docs/<library>/…`) is listed only when a registry item points to it (`isIndexableDocsPage` in `lib/registry.ts`); the rest are noindex.
