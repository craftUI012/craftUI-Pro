## The three artefacts

| Artefact                                         | Committed?      | Written by            | Read by                                                          |
| ------------------------------------------------ | --------------- | --------------------- | ---------------------------------------------------------------- |
| `registry/<library>/<name>.tsx`                  | yes             | you                   | `shadcn build`, the docs site (`ComponentSource`), the home page |
| `registry.json`                                  | yes             | you                   | `shadcn build`, `components/command-box.tsx` (item names)        |
| `public/r/<name>.json`, `public/r/registry.json` | yes (currently) | `pnpm registry:build` | the shadcn CLI on users' machines (free items and the index)     |
| `registry-paid/<name>.json`                      | yes (currently) | `pnpm registry:build` | `app/r/[file]/route.ts`, for buyers only (see [Paid items](#paid-items)) |

## What `pnpm registry:build` does

It runs `scripts/build-registry.mjs`, which copies `registry.json` to `node_modules/.cache/registry/`, sets its `homepage` from `NEXT_PUBLIC_SITE_URL` (ignored if localhost), and then runs:

```bash
shadcn build node_modules/.cache/registry/registry.json --output ./public/r
```

The committed `registry.json` is never modified. See [Changing the domain](/docs-admin/guides/changing-the-domain).

### What `shadcn build` does

For every item in `registry.json`, it:

1. Reads each `files[].path` from disk.
2. Inlines the file **contents** into the item.
3. Adds `$schema: https://ui.shadcn.com/schema/registry-item.json`.
4. Writes `public/r/<item.name>.json`.

It also writes `public/r/registry.json`, the index of all items. Because `public/` is served statically, the files are available at `https://<site>/r/<name>.json`.

Then the script moves every **paid** item's JSON out of `public/r/` into `registry-paid/`, which isn't public. See [Paid items](#paid-items).

A built item looks like this:

```json
{
  "$schema": "https://ui.shadcn.com/schema/registry-item.json",
  "name": "your-component",
  "title": "Your Component",
  "description": "A placeholder component...",
  "files": [
    {
      "path": "registry/components/your-component.tsx",
      "content": "import type { HTMLAttributes } from \"react\";\n...",
      "type": "registry:ui",
      "target": "components/ui/your-component.tsx"
    }
  ],
  "type": "registry:ui"
}
```

## What happens on the user's machine

```bash
npx shadcn@latest add https://<site>/r/<name>.json
```

1. The CLI fetches the JSON.
2. It installs `dependencies` and `devDependencies` with the user's package manager.
3. It recursively installs `registryDependencies` (shadcn names like `button`, or full URLs).
4. It **rewrites imports** such as `@/lib/utils` to match the user's own `components.json` aliases.
5. It writes each file to its `target`, or to the default folder for its `type`.
6. It merges any `cssVars` and `css` into the user's global CSS.

<Callout title="Write imports against this repo's aliases">
  Inside `registry/*`, import helpers as `@/lib/utils`, and
  shadcn primitives as `@/components/ui/<x>` (declared in
  `registryDependencies`). The CLI rewrites these for each user. Never import
  site-only code like `@/hooks/use-feedback` or `@/constants/*` from a
  registry file, because it won't exist in the user's project. Files of
  one item import each other relatively (`./hero-section-02-wheel`): every
  file in a library folder installs into the same folder, so the paths hold
  in both places.
</Callout>

## Images a component ships with

Put the file in `public/images/`, and reference it from the component by its root-relative path (`"/images/<file>"`). After `shadcn build`, `scripts/build-registry.mjs` rewrites those paths in the published `public/r/*.json` to `<homepage>/images/<file>`. Installed components then load the image from this site, served by the deploy's CDN, with no separate upload. The source keeps the relative path, so the site's own previews are unchanged. Keep these files web-sized (for example a 2400px WebP): every visitor of every site using the component downloads them.

## How the site reads the source

`lib/registry.ts`:

```ts
getRegistryUiSourceCandidates({ name }); // → [the item's first `files` path in registry.json]
getDemoSource(name); // → examples/<name>.tsx, or null
getRegistrySource(name); // → first candidate that exists, or null
```

`components/component-source.tsx` resolves code in this order:

1. `examples/<name>.tsx`, the demo file (the `examples/` folder doesn't exist yet).
2. The item's first file in `registry.json`, the component itself. List the main file first.
3. Or the explicit `src="path/to/file.tsx"` prop, which wins if you pass it.

The code is then formatted (`lib/format-code.ts`) and highlighted (`lib/highlight-code.ts`) on the server.

## Registry install buttons on the site

- **`CommandBox`** (home page) shows `<pm> shadcn add` followed by flipping item names taken from `registry.json`.
- **`RegistryAddButton`** shows `shadcn registry add <registryName>`, which is the command for adding the whole namespaced registry once it's listed in the shadcn directory.

## Paid items

Every library item (one with `meta.library`) is **paid** unless `registry.json` gives it `"free": true` in `meta`. `isPaidItem()` in `lib/registry.ts` is the one place that decides.

### Where a paid item's code can and can't be reached

| Place | Free item | Paid item |
| --- | --- | --- |
| `https://<site>/r/<name>.json` | Static file in `public/r/` | `app/r/[file]/route.ts`: needs `?t=<install token>` and access in the database |
| `https://<site>/r/<product-code>.json` (e.g. `SEC-0003`) | Same as by name | Same as by name |
| Docs page HTML | Source rendered by `ComponentSource` | **Never** in the page. The Code tab is `components/paid-source.tsx` |
| Code tab | Source | Plans with checkout buttons (`components/paywall.tsx`), or, for an owner, the source from `/api/source/<name>` |
| Copy for AI | Copies the source | Locked (opens the plans); an owner's copy fetches the source from `/api/source/<name>` |
| Install command in the toolbar | Plain command | Locked (opens the plans); an owner copies the command with their token |
| `public/r/registry.json` (index) | Listed | Listed (names and file paths only, never contents) |

The live preview itself still ships the component's compiled, minified JavaScript to the browser: it has to, to render. Only the readable source and the installable files are gated.

### Install tokens

An owner's install command is `npx shadcn@latest add https://<site>/r/<name>.json?t=<token>`. The token (`lib/install-token.ts`) is the user's ID plus an HMAC-SHA256 signature made with `BETTER_AUTH_SECRET`, so only this server can issue one.

- It **never expires** and there's no reset. The route checks the database on **every** install, so a refunded buyer or a lapsed yearly plan stops working at once.
- The user gets their token from `/api/access` (read by `hooks/use-access.ts`). The token is only in the copied command, never in the visible text.
- Changing `BETTER_AUTH_SECRET` invalidates every token. Owners just copy the command again.

### What the route answers

| Request | Response |
| --- | --- |
| Paid item, no token or a forged one | `401`, with a message pointing to the item's docs page. The shadcn CLI prints it |
| Valid token, but the user doesn't own the item | `403`, with a link to pricing |
| Valid token, all-access or a purchase of the item's product code | `200`, the item JSON, `Cache-Control: private, no-store` |
| An unknown name or code | `404` |

Installs are recorded in PostHog: free items by `proxy.ts`, paid items by the route itself. A granted paid install is `registry_item_fetched`, tied to the buyer's user ID. A refusal is `registry_access_denied`, with `reason` `no_token` or `no_access`, so refusals never count as installs.

### Making an item free

Add `"free": true` to its `meta` and run `pnpm registry:build`. Its JSON moves back to `public/r/`, and the docs page shows its source again. To make it paid again, remove the flag and rebuild.
